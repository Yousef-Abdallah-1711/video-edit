# Video Edit

Use this skill when the user gives a video path and wants a complete edit. The single invocation is `$video-edit <video-path> [enhanced-audio-path]`. Treat the path as the source and complete the review, edit, export, and final checks in that turn. Do not alter the source file. Detect whether the recording is a prepared tutorial or a live workshop; when it is a live workshop being made into a course lesson, use the course-conversion workflow below by default.

## Workflow

1. **Inspect the source.** Use `scripts/video_edit.py prepare <video-path>` to probe streams and duration, extract a review MP3, detect candidate silences, create visual samples, and write an edit plan JSON beside the source in a dedicated `<stem>_edit` directory. Review the sample frames across the whole video and inspect the opening, ending, app changes, and every likely live-meeting segment. Use Arabic/Egyptian Arabic speech transcription; preserve English technical terms and source timestamps. If no transcription capability is available, listen in manageable chunks and do not present silence detection as a transcript.
2. **Build a source-time edit plan.** Update the generated JSON's `cuts` and `freezes` only after reviewing the corresponding speech and picture. Cut exact duplicate lines, abandoned sentence starts, obvious stutters, and filler that contributes nothing. Keep meaningful restatements, lists, examples, and explanations that add new information. For a live workshop, also identify and remove greetings, roll call, opening Google Meet/Zoom/Teams screens, waiting for attendees, mic checks, participant names and hand-offs, unrelated chat, breaks, and the audience Q&A close. Keep a participant question only when its answer teaches the lesson; remove the participant's identity and the facilitator hand-off. Preserve coding/tool sessions that happen to use the word “session.” Each cut needs source-time `start`, `end`, and a short reason. Keep enough handles for natural joins.
3. **Review long pauses and screen waits.** Candidate detection defaults to `silencedetect` at `-34 dB` for longer than 3 seconds. Treat detections as candidates, not automatic cuts. Remove dead air, but preserve a useful loading/demo step; shorten an essential wait with a speed-up or a brief “جاري الفحص” / “جاري التحقق” label. Retain a short natural pause at speech edges. Do not cut quiet speech, breaths needed for cadence, or deliberate pauses. Merge overlapping cuts and verify the kept intervals.
4. **Convert workshop packaging into course packaging.** If the opening shows an unrelated previous lesson, meeting lobby, desktop, or setup screen, replace it with a concise lesson title card while keeping the narration aligned. Use a custom intro video via `--intro-video` and remove the same-duration opening source span from the edit plan; the custom intro must contain the matching source audio segment, or have deliberate silence if no narration should play. Use a clean course title and a short accurate subtitle, not invented lesson claims. Add brief timed chapter callouts as an SRT via `--chapters-srt` when app/context jumps need explanation. Keep labels on screen briefly; do not place them over important controls or dense code. If a jump is self-explanatory, leave it clean.
5. **Clean the captured screen.** Never add a decorative frame. Inspect for active meeting tiles, tabs, account names, notification banners, private messages, and taskbar popups. Remove or blur meeting/private material when it appears. Browser chrome can be cropped or masked only if URLs, controls, and side-by-side panes are not needed for the lesson. Leave `crop` null when the full screen matters; the renderer fits the full source inside 16:9 with black bars when aspect ratios differ. For ultrawide recordings, prefer selective zooms/reframes of the relevant pane over a crop that loses instructional content.
6. **Repair picture dropouts when justified.** Use a freeze frame only for an accidental picture dropout while useful narration continues. Never cover intentional black or a meaningful interface change.
7. **Use the series intro only for that series.** The bundled `assets/payment_gateway_intro.mp4` belongs to the payment-gateway series. For other videos, use `--no-intro` or an accurate custom lesson title card. Never reuse an unrelated intro.
8. **Render and optional enhanced audio.** Run `scripts/video_edit.py render <edit-plan.json>`. Use `--intro-video <path>` and/or `--chapters-srt <path>` when appropriate. If enhanced audio is supplied, use `--enhanced-audio <path>`; it must cover the complete edited timeline, including any intro. Compare duration before muxing. The renderer uses H.264 MP4 at 30 fps / 2560x1440, 48 kHz stereo AAC, and exports a standalone 192 kb/s MP3. When making a course version, render to a separate `<stem>_edit/course/` folder so the first clean export is preserved.
9. **Make the project reviewable.** Keep the JSON edit plan, chapter SRT, title-card asset, filter graph, and render summary beside the course exports. If Kdenlive is available, create a project with the same source in/out cuts and any intro clip; verify that the timeline duration matches the render.
10. **Check the exports.** Probe the MP4 and MP3 with `ffprobe`; confirm streams, duration, resolution, and audio format. Inspect opening, middle, chapter transitions, representative edits, and ending. Listen to the joins and recheck every removed live exchange. Correct black flashes, bad joins, cut-off words, or crop damage before reporting exact output paths and any source-screen material that remains.

## Helper commands

```text
python <skill>/scripts/video_edit.py prepare "D:\path\to\source.mp4"
python <skill>/scripts/video_edit.py render "D:\path\to\source_edit\source_edit_plan.json" [--enhanced-audio "D:\path\to\enhanced.mp3"]
python <skill>/scripts/video_edit.py render "D:\path\to\source_edit\source_edit_plan.json" --no-intro
python <skill>/scripts/video_edit.py render "D:\path\to\source_edit\source_edit_plan.json" --intro-video "D:\path\to\course_title.mp4" --chapters-srt "D:\path\to\chapters.srt" --output "D:\path\to\source_edit\course\source_course_final.mp4"
python <skill>/scripts/video_edit.py title-card --output "D:\path\to\course_title.mp4" --title "درس السيو التقني عمليًا" --subtitle "الأداء وأدوات جوجل" --duration 6.3 --audio-from "D:\path\to\source.mp4" --audio-start 0
```

Use `mask_regions` in the plan for privacy/desktop masks in source-frame pixels, for example `[{"x":0,"y":0,"width":2580,"height":86,"start":0,"end":175}]`. `start`/`end` are optional source timestamps in seconds; omit them to blur that rectangle for the whole source. This supports removing a meeting popup only while it is on screen, without obscuring later lesson content. The renderer applies a strong blur before fitting the frame to 16:9. Check every screen layout and mask interval; do not cover a URL, control, or code needed for the lesson.

The original source remains untouched. Review artifacts and the edit plan stay under `<stem>_edit`; a course render and its separate MP3, project, chapter SRT, title card, filter graph, and summary belong under `<stem>_edit/course/`. Use the bundled intro only for the payment-gateway series; all other lessons need a title card that matches their subject.
